Requirements Review · Product Proposal

AgentHub 产品评估与需求提案

以企业需求方视角，对 AgentHub 全站页面与功能做一次完整体检：先给出当前产品成熟度评估，再提出下一阶段希望开发方实现的产品内容与验收标准。

评估对象 AgentHub 企业智能体平台（V1） 评估视角 需求方 / 产品负责人 日期 2026-10-02 范围 全站页面 · 功能 · 体验
总体判断

工程完成度 高于 产品完成度：后端闭环、组织权限、版本管理与可观测链路扎实；对话体验、知识库深度、数据呈现三处短板最影响使用。

建议节奏

V1.5 体验补全（约 3 周）→ V1.6 数据与效率（约 1 个月）→ V2.0 平台化（季度级）。先补体验闭环，再谈平台化。

本轮最该先做

① 导航与信息架构重构　② AI 对话体验补齐　③ 知识库文档生命周期管理

01

项目总体评估

基于对仓库代码（前端 15 个页面、后端 11 个 API 模块）与页面实际截图的检查，从产品视角给出定位判断、优点与差距。

定位判断

对标 Dify / Coze 空间 / RAGFlow 一类的企业级 AI Agent 平台。

  • 闭环完整：用户 → Agent → 知识库 → RAG → 工具 → LLM → 执行日志，是能支撑真实业务的底子；
  • 差异化优势：Agent 版本化（创建/发布/回滚）+ 执行链路全量可观测；
  • 当前阶段：V1 功能验收基本达成，处于「能用」向「好用」过渡，体验细节与深度功能未跟上工程完成度。

做对了什么（值得保留）

  • 工程交付质量高：一键脚本、Docker、CI/CD、pytest、模块设计文档齐全，接手成本低；
  • 组织多租户 + 四角色 RBAC 严谨：owner 转让/解散有保护，角色按组织独立；
  • Agent 版本化是平台级差异点，B 端管理刚需；
  • SSE 流式对话 + 执行日志（LLM/RAG/Tool/Token）为可观测性打了好底子；
  • 工具 Schema + 测试运行、知识库检索测试、表单实时预览等小闭环均已落地；
  • 需求文档与验收标准齐全，V1/暂缓范围界定清晰。

主要差距（详见问题清单）

  • 信息架构：导航归属逻辑不统一，模型供应商页面无导航入口；
  • AI 对话：无停止/重试/复制、无引用来源交互、会话不可管理，核心场景体验粗糙；
  • 知识库：文档生命周期缺失（无文档列表/删除/重解析/分片预览），检索测试结果不可见；
  • 数据呈现：工作台只有数量卡片，执行监控无图表、无步骤时间线；
  • 体验基建：加载/空/错三态粗糙，无引导；无个人中心，头像仅支持 URL。

03

模块成熟度评估

八个功能维度的现状打分（5 分制）。口径：基于本次对代码与界面现状的检查，按「功能完整度 × 体验完成度」定性打分，非系统统计指标。

读图要点：认证/权限、Agent 版本、工程化三块是当前底座；知识库、对话、可观测性的「呈现层」是下一阶段主战场；界面与信息架构拖累了整体体验分。

04

关键问题清单

按影响程度排序。P0 为「不做就无法宣称好用」的体验闭环问题；P1 为数据与效率问题。

问题 1 · 导航信息架构归属混乱P0

「组织设置 / 成员管理」挂在「我的组织」下却又是独立入口；「知识库 / 工具」挂在「智能体」下，层级逻辑不统一；模型供应商页面无任何导航入口，功能被藏在路由里。影响：用户找不到功能，平台能力被浪费。

问题 2 · AI 对话核心场景体验不完整P0

无停止生成/重新生成/复制/删除；无 Markdown 与代码块渲染增强；需求文档承诺的「查看引用来源」在对话中不可见（RAG 命中无法展示/交互）；会话不可重命名、归档、搜索。影响：这是用户每天用的页面，直接决定留存。

问题 3 · 知识库文档生命周期缺失P0

上传后无文档列表，无法删除、重新解析；解析失败的原因不可见；无分片（Chunk）预览；检索测试只出 top_k 数字，不展示命中的内容/文档/页码/分数。影响：RAG 效果无法诊断，「企业文档沉淀」的价值打折扣。

问题 4 · 加载/空/错三态粗糙，缺引导P0

多处出现裸文本「加载中…」；空状态只有一行说明；无错误重试；新用户无 onboarding。影响：第一印象像内部 demo，不像产品。

问题 5 · 工作台与执行数据呈现浅P0

工作台只有四个数量卡片，无趋势、无 Token/成本、无活跃度；「最近执行成功率 0%」对空数据不友好；执行监控无图表、无步骤时间线。影响：管理者无法回答「用得好不好、花多少钱」。

问题 6 · 成员协作缺少邀请链路P1

只能按邮箱添加（对方须已注册），无邀请链接/邀请码/待接受状态；角色变更无留痕。影响：组织扩张成本高，安全审计无据可查。

问题 7 · 工具生态单薄P1

当前以 HTTP/计算器为主，无内置工具库/分类浏览；对话中工具调用无回放标注；无按角色/Agent 授权与调用审计。

问题 8 · 账户与个人资产缺位P1

无个人中心（改密码/头像/会话管理）；Agent 头像仅支持 URL 输入而非上传；无「我的跨 Agent 会话」总览。

05

需求提案（下阶段我想做的产品内容）

以需求方身份提出。P0 = 下轮迭代必须交付（体验闭环）；P1 = 短期增强（数据与效率）；P2 = 中长期平台化。每条附验收标准，可直接进入开发排期。

P0 · 体验闭环（下轮迭代，约 3 周）

P0-1

导航与信息架构重构

P0

需求：统一侧边栏归属逻辑：一级导航固定为「工作台 / 我的组织 / 智能体 / 知识库 / 工具 / 运行 / 模型管理」，组织设置与成员管理收归组织详情或组织切换器内，删除重复入口；补齐「模型管理」导航项；OrgSwitcher 展示组织角色与成员数。

验收标准
· 全站无重复入口、无死链；· 模型供应商页可从导航直达；· 任何页面 ≤ 3 次点击可达；· 侧边栏按角色（owner/admin/member/viewer）正确显隐管理项。
P0-2

AI 对话体验补齐

P0

需求：消息操作（复制 / 重新生成 / 停止生成 / 删除）；Markdown、代码块高亮与流式渲染；引用来源卡片——RAG 命中的文档/分片以可点击卡片展示，点击展开内容与页码，可跳转知识库文档；会话管理（重命名 / 归档 / 删除 / 搜索历史会话 / 清空上下文）；上下文长度指示。

验收标准
· 生成中可停止、停止后可重新生成；· 命中知识库的回答必须带可展开的引用来源；· 会话可重命名/归档/搜索；· 代码块可复制、可高亮。
P0-3

知识库文档生命周期管理

P0

需求：文档管理列表（文件名/大小/状态：解析中·成功·失败/错误原因），支持删除、重新解析；分片（Chunk）预览与数量统计；检索测试结果可视化——展示命中片段内容、所属文档、页码、分数，支持调整 top_k 与相似度阈值；KB 与已关联 Agent 的关系展示。

验收标准
· 上传 → 解析 → 失败/成功全状态可见且可操作；· 检索测试必须返回「内容/文档/页码/分数」四要素；· 删除文档后向量库同步清理；· 文档更新可增量重解析。
P0-4

个人中心与体验三态

P0

需求：个人中心（头像上传、修改密码、我的会话、退出全部设备）；Agent/组织头像支持本地上传；全局统一加载骨架屏、空状态插画与引导文案、错误重试按钮；新用户 onboarding（建组织 → 建 Agent → 传文档 → 发起对话四步引导）。

验收标准
· 头像可上传且格式/大小有校验；· 全站无裸「加载中…」文本；· 每个空状态给出下一步动作；· 新注册用户可见四步引导。
P0-5

工作台数据升级

P0

需求：工作台增加近 7/30 日趋势图（执行量、成功率、平均耗时）；Token 消耗与估算成本；最活跃 Agent / 知识库排行；「最近执行」列表可直接点击进入详情。空数据时给出引导而非「成功率 0%」。

验收标准
· 三张趋势图数据来自执行日志且时间范围可切换；· 成本按「输入/输出 Token × 单价」可解释；· 空数据态与有数据态分别有正确表达。

P1 · 数据与效率（短期迭代，约 1 个月）

P1-1

执行监控可视化

P1

详情页升级为步骤时间线：LLM / RAG / Tool 各步骤的输入输出可展开、耗时与 Token 逐项列出；列表支持时间范围/Agent/状态筛选与 CSV 导出；失败执行可一键定位到对应对话并重试。

验收标准
· 一次执行的每一步骤均可展开看入参/出参/耗时；· 可按时间范围导出；· 失败项可直接跳到对话上下文。
P1-2

工具生态扩展

P1

内置工具库分类浏览（计算 / 搜索 / 天气 / 数据库 / HTTP / 自定义函数）；对话中工具调用以气泡标注（如「已调用 汇率查询 · 12ms」）并可展开入参出参；工具按角色与 Agent 双重授权，调用留痕。

验收标准
· 至少内置 5 类工具模板；· 对话气泡可看到工具调用过程；· 执行日志可按工具维度检索。
P1-3

模型管理增强

P1

模型供应商页进入导航；增加模型目录（按供应商/能力/上下文长度浏览）；每个 Agent 展示模型可用性状态；供应商用量统计（按模型/日期）；密钥加密与权限提示清晰化。

验收标准
· 导航直达；· 新建 Agent 时可按能力筛选模型；· 用量报表按供应商/模型/日期可查。
P1-4

成员协作与邀请

P1

邀请链接/邀请码（含有效期与角色预设），未注册邮箱可先邀请、注册后自动入组；角色变更留痕（操作者/时间/前后角色）；成员列表显示最近活跃与资源归属。

验收标准
· 被邀请者注册后自动加入组织并获预设角色；· 角色变更可在组织审计中追溯。
P1-5

Agent 模板库与版本对比

P1

行业模板（客服 / 数据分析 / 文档问答 / 工单分类）一键创建；任意 Agent 可「存为模板」；版本历史支持两版本 diff（Prompt/模型/参数高亮差异）；列表支持分页与批量停用。

验收标准
· 模板创建后一次配置即可对话；· 版本 diff 可见字段级差异。

P2 · 平台化（中长期，季度级）

P2-1

工作流编排

P2

可视化工作流画布：多步骤、条件分支、人工审核节点、并行执行；节点可复用已有 Agent/工具/知识库检索；支持导入导出工作流定义（JSON）。

P2-2

多 Agent 协作与记忆

P2

子 Agent / 编排 Agent（manager-worker 模式）；会话记忆与长期记忆库（按用户/组织维度沉淀可检索的事实）；记忆的开启/清空/审计由管理员控制。

P2-3

自动化触发

P2

定时任务与 Webhook 触发 Agent 执行（如每日 9:00 生成经营摘要推送）；触发记录并入执行日志；失败重试策略可配置。

P2-4

API Keys、配额与审计

P2

组织级 API Key 管理与按 Key 配额/限流；全量审计日志（登录/资源变更/工具调用/权限变更）；为商业化（套餐/计费）预留数据底座。

P2-5

国际化与移动端

P2

i18n（中/英优先，文案抽离）；移动端 H5 适配（对话与监控优先）；无障碍与深色模式。

下轮迭代验收标准

P0 需求全部交付后，需求方将按下述清单逐项验收，全部通过才视为迭代完成。

  • 导航：全站无重复入口、无死链；模型管理可从导航直达；任何页面 ≤ 3 次点击可达；
  • 对话：可停止、可重新生成、可复制；命中知识库的回答带可展开的引用来源；会话可重命名/归档/搜索；
  • 知识库：文档全状态可见可操作；检索测试返回内容/文档/页码/分数；删除文档同步清理向量；
  • 账户与三态：头像可上传；全站无裸「加载中…」；每个空状态有下一步动作；新用户有四步引导；
  • 工作台：7/30 日趋势图可用；成本口径可解释；空数据态表达正确；
  • 回归：既有 pytest 全部通过；新增用例覆盖对话引用、文档生命周期、导航权限；
  • 体验：桌面与移动端（H5 适配范围）均无布局破损；关键操作响应 ≤ 300ms（本地环境）。
